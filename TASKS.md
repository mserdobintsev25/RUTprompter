# RUTprompter — план работы

Контекст использования: не эфир, а запись коротких вертикальных видео
(кулинарные форматы с диалогом, шуточный контент) с партнёром. См.
"Сценарий использования" в `CLAUDE.md`.

**Жёстко запрещено**: голосовые команды управления ("стоп", "дальше" и
т.п.) — см. "Жёсткое ограничение" в `CLAUDE.md`. Голос только пассивно
трекается, никогда не интерпретируется как команда.

## Этап 1 — минимальный каркас приложения
- [x] `Package.swift`: executable target под macOS (аналогично Peel).
- [x] Окно оператора: текстовое поле для скрипта + кнопка Play/Pause
      (без логики распознавания речи).
- [x] Определение второго экрана (`NSScreen.screens`), открытие
      отдельного полноэкранного окна вывода на нём с тем же текстом,
      синхронизированным через общий observable-стейт.
- [x] Переключатель "зеркалировать второй экран" — применяет
      горизонтальный flip только к окну вывода.
- Критерий готовности: при подключении второго монитора по HDMI на
  нём появляется полноэкранный текст, зеркалируется независимо от
  окна оператора; окно оператора всегда в нормальной ориентации.

## Этап 2 — темы и читаемость
- [x] Пресеты цветовых схем (чёрный/белый, жёлтый/чёрный,
      чёрный/белый инверс) + кастомный выбор цвета текста, фона,
      подсветки текущей строки.
- [x] Настройка размера шрифта, межстрочного интервала, отступов.
- [x] Подсветка "текущей" строки в окне вывода.
- Критерий готовности: смена темы в окне оператора мгновенно
  применяется к окну вывода; настройки сохраняются между запусками.

## Этап 3 — распознавание речи и автоподгон скорости
- [x] Интеграция `SFSpeechRecognizer` (on-device), с поддержкой
      смешанной ru+en речи — в текстах часто встречаются иностранные
      слова/термины, одной ru-RU модели может не хватать.
- [x] Алгоритм сопоставления распознанных слов с текстом скрипта
      (окно поиска вперёд, устойчивость к ошибкам распознавания).
- [x] Отличение голоса читающего от голоса собеседника ("диаризация")
      — на старте: контентное сопоставление само отсеивает реплики не
      из скрипта + опция привязки к конкретному входному
      микрофону/каналу, если у каждого свой мик. Полноценная
      speaker-embedding диаризация — отдельная, более трудоёмкая
      задача, не блокер MVP (детали — в `CLAUDE.md`).
- [x] Ручной override скорости: оператор может подвинуть позицию
      вручную в любой момент, трекинг речи должен "отпустить" и
      подхватить заново с новой позиции, а не тянуть обратно.
- [x] Fallback-режим: если распознавание недоступно (нет доступа к
      микрофону, модель не загрузилась) — обычная прокрутка по
      заданной постоянной скорости, без падения функциональности.
- [x] Расчёт сглаженного текущего WPM по таймстемпам распознанных слов.
- [x] Плавное управление scroll offset на основе текущей позиции
      указателя (без рывков при временной потере синхронизации).
- Критерий готовности: при чтении текста вслух вдвоём прокрутка
  следует за читающим, не сбивается от реплик собеседника, ручной
  override работает предсказуемо, а при выключенном микрофоне
  приложение не ломается.

## Этап 4 — оценка времени и целевая длительность
- [x] Расчёт ETA = (оставшиеся слова) / (сглаженный WPM), обновляется
      непрерывно.
- [x] Отображение ETA в окне оператора (и опционально — в окне
      вывода, если включено в настройках).
- [x] Целевая длительность видео/дубля — задаётся на скрипт целиком;
      показывать, укладывается ли текущий темп в цель ("+15 сек к
      цели" и т.п.) — без жёсткого "эфирного" рестрикшена, просто как
      подсказка оператору.
- [x] Индикатор-плашка приближения к концу раздела/маркера (не только
      конца всего текста) — полезно, когда скрипт разбит на смысловые
      куски (например, шаги рецепта).
- Критерий готовности: ETA и индикатор цели ощутимо меняются при
  изменении темпа речи, а не держатся фиксированным числом с самого
  старта.

## Этап 5 — удобство оператора
- [x] Горячие клавиши: пауза, ручная перемотка, +/- скорость, +/-
      шрифт.
- [x] Маркеры/закладки в тексте для быстрого перехода между разделами
      (например, шагами рецепта или репликами).
- [x] Импорт текста (Markdown / вставка из буфера) с сохранением
      разбивки на абзацы, а не голый plain text.
- [x] Блокировка редактирования текста во время Play (с возможностью
      быстрой точечной правки без выхода из режима) — чтобы случайное
      касание не улетело в середину скрипта во время записи.

## Этап 6 — пост-анализ дублей
- [x] После остановки прокрутки — сводка по дублю: реальное время
      чтения, график фактического WPM по ходу текста, места, где темп
      сильно проседал/ускорялся.
- [x] Сохранение истории дублей внутри сессии (хотя бы в памяти, без
      необходимости делать полноценную базу на старте).

## Требует ручной проверки
- [ ] Режим «По голосу» вживую: запрос доступа, чтение вслух вдвоём,
      реплики собеседника не двигают текст, ручная перемотка.
- [ ] Реальный второй монитор по HDMI: автооткрытие на весь экран,
      отключение/подключение кабеля.
- [x] Офлайн-модели ru-RU и en-US установлены — проверено: статус «Слушаю (ru-RU + en-US, на устройстве)».
- [x] Сквозной тест голоса без звука (аудиофайл → распознавание →
      прокрутка): тишина 6 с, чтение, болтовня, чтение. Текст идёт за
      речью по словам, болтовня его не сдвигает, после неё трекинг
      подхватывает место за ~1 с, темп измеряется верно (~150 сл/мин).
      Найдено и исправлено: две модели (ru+en) одновременно обрывали
      друг друга — оставлена одна.
- [ ] Живой микрофон: почитать пару строк самому.
- [ ] После каждой пересборки macOS заново спрашивает доступ к микрофону
      и распознаванию (ad-hoc подпись меняет отпечаток). Решение —
      постоянный сертификат для подписи (self-signed в «Связке ключей»).
